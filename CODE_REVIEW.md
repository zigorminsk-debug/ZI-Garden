# Ревизия кода ZI Garden (GardenCalendar) — отчёт

Дата проверки: 16.09.2026. Проверены: все исходники `src/` (38 классов), тестовый набор `test/`,
ресурсы `res/`, `AndroidManifest.xml`, скрипты `build.sh` / `test.sh`.

Способ проверки: компиляция всего кода Eclipse-компилятором (ECJ 3.39, Java 8, android.jar API 34),
прогон штатного набора `LogicTest`, компиляция с включёнными предупреждениями
(null-анализ, утечки, dead code и др.), валидация XML и перекрёстных ссылок ресурсов, ручная ревизия.

## Критические ошибки (исправлено)

1. **Проект не компилировался: отсутствовали 7 классов.** Функция «Справочник болезней» была
   объявлена в манифесте (`.DiseaseActivity`) и использовалась `test/LogicTest.java`, но файлов
   не было в git: `Disease.java`, `DiseaseActivity.java`, `DiseaseDataA/B/C.java`, `DiseaseDb.java`,
   `RemoteDiseases.java`. Восстановлены из релизного архива `GardenCalendar-src-v2.5.tar.gz` (лежит
   в корне репозитория) — это та же версия v2.5, что собирает `build.sh`.
2. **Отсутствовали 19 ресурсов `res/drawable-nodpi/`:**
   `banner_garden.jpg`, 10 фото болезней `dz_*.jpg`, 8 схем обрезки `scheme_prune_*.jpg`.
   На них ссылаются `Scheme.java`, `R.drawable`, тесты. Восстановлены из того же архива.
3. **В `Storage.java` не было методов `diseaseUpdateUrl()` / `setDiseaseUpdateUrl()`**
   (компиляция падала в `RemoteDiseases.java:34`). Добавлены по эталону из архива.
4. **`MainActivity`, `CropInfoSheet`, `TaskDialog` в git были старее архива** и не содержали
   точек входа в справочник болезней (`RemoteDiseases.refreshAsync` при старте, кнопки «🦠 Болезни»,
   ограничение высоты диалогов). Файлы синхронизированы с версией v2.5 из архива.

## Баги логики (исправлено)

5. **`Planner.shoppingList(int i)` игнорировал своё окно.** Для любого периода (7/14/30 дней)
   план строился по `tasks(21)`, поэтому в список покупок «на 30 дней» не попадали материалы
   для работ, впервые выпадающих на 22–30-й день. Проверено эмпирически: терялось 2 из 3
   «поздних» материалов текущего сезона. Теперь окно = `tasks(Math.max(i, 21))`.
6. **`Weather.iconFor()`: WMO-коды 80–82 (ливневый дождь) показывали значок снега 🌨️**
   при тексте «ливень». Исправлено на 🌧️ (85–86 — снежный ливень — остались 🌨️).
7. **`Dates.diffDays()` давал ошибку на 1 день при переводе часов** (Украина, сутки 23/25 ч:
   усечение `мс / 86400000`). Заменено на `Math.round`. Проверено на обоих переходах 2026 г.
   (29.03 и 25.10, Europe/Kiev): корректно.
8. **`test.sh` падал, если нет `/usr/lib/jvm/java-21-openjdk-amd64`** — жёстко заданный
   `JAVA_HOME`. Добавлены те же запасные варианты, что в `build.sh`.

## Замечания (не влияют на работу, исправлять по желанию)

- `Notifications.MAX_ALARMS` — неиспользуемая константа.
- `Notifications.scheduleAll()` пересчитывает `planner.tasks(21)` 15 раз в цикле по дням —
  чистая оптимизация, на поле не влияет.
- `AlarmReceiver` вызывает `startService(RescheduleService)`: на Android 8+ из фона сервис
  не стартует, исключение перехвачено — после 14 дней без открытия приложения цепочка напоминаний
  не продлевается до следующего входа/перезагрузки (переживается `BootReceiver`). По-хорошему —
  WorkManager/JobScheduler.
- `Geo.label()` (Geocoder) вызывается в UI-потоке — теоретический риск ANR при медленном геокодере.
- `RemoteDiseases.refreshAsync()` не вызывает `HttpURLConnection.disconnect()` при ответе ≠200
  (мелочь, соединение закроет GC с задержкой).
- Статический `DecimalFormat Planner.DF` не потокобезопасен (используется из одного потока — сейчас ок).
- `build.sh`: нумерация шагов смешанная (`[1/7]…[3/7]`, далее `[4/8]…[8/8]`) — косметика.
